# 远程传感器数据采集及可视化程序技术设计文档

## 1 文档概述

### 1\.1 文档目的

本文档为基于 C\+\+、Boost、Qt 实现的远程传感器数据采集与可视化系统的技术设计文档，明确系统整体技术架构、分层模块职责、核心技术实现方案、重点难点及优化策略，为项目开发、调试、维护及迭代提供统一技术依据。

### 1\.2 适用范围

本文档适用于 Windows/Linux 跨平台传感器数据采集上位机软件，涵盖网络通信、数据解析、业务处理、实时可视化、数据持久化全流程技术设计。

### 1\.3 技术栈选型

|技术组件|版本/说明|核心用途|
|---|---|---|
|C\+\+|C\+\+17/20|系统核心业务逻辑、数据处理、算法实现|
|Boost|最新稳定版|Boost\.Asio异步网络通信、Boost\.JSON/Serialization序列化、Boost\.Thread多线程、Boost\.Chrono高精度定时、Boost\.PropertyTree配置解析|
|Qt|Qt6（兼容Qt5）|跨平台GUI界面、实时数据可视化、信号槽跨线程通信、界面交互逻辑|
|可视化组件|QCustomPlot/Qt Charts|传感器实时曲线绘制、数据图表展示|
|可选扩展组件|SQLite/Protobuf/spdlog|本地数据存储、标准化二进制协议、日志管理|

## 2 系统总体架构

### 2\.1 架构设计原则

- **分层解耦**：各层级职责单一、依赖单向，便于模块迭代与维护；

- **线程隔离**：网络IO线程、业务处理线程、UI主线程严格隔离，杜绝UI卡顿、线程崩溃；

- **异步非阻塞**：基于Boost\.Asio异步IO模型，保障高频数据采集的实时性与稳定性；

- **高容错可扩展**：支持断线重连、异常数据过滤、多设备并发接入，预留功能扩展接口。

### 2\.2 整体分层架构

系统采用五层分层架构，自上而下依次为UI可视化层、业务逻辑管理层、通信传输层、设备协议适配层、持久化与支撑层，具体结构如下：

UI可视化层（Qt） → 业务逻辑管理层（C\+\+核心） → 通信传输层（Boost\.Asio） → 设备协议适配层 → 持久化\&工具支撑层

#### 2\.2\.1 UI可视化层（Qt）

系统人机交互核心，仅运行于Qt主线程，负责所有界面展示与交互事件处理。核心功能：实时数据曲线展示、数字仪表盘、设备状态指示灯、数据告警弹窗、参数配置、历史数据查询、数据导出、日志展示。采用QCustomPlot作为核心绘图组件，支持硬件加速、动态数据刷新。

#### 2\.2\.2 业务逻辑管理层（C\+\+核心）

系统数据处理中枢，衔接网络通信层与UI层。核心功能：采集任务调度、传感器数据预处理（滤波、异常值剔除）、阈值告警判断、跨线程数据分发、多设备状态管理、任务启停控制。通过线程安全消息队列实现数据流转，隔离底层通信与上层UI。

#### 2\.2\.3 通信传输层（Boost\.Asio）

系统网络通信核心，独立IO线程池运行，不占用Qt主线程事件循环。核心功能：TCP/UDP异步收发、连接管理、心跳保活、断线自动重连、收发缓冲区管理、网络异常处理。支持客户端主动连接、服务端被动上报两种部署模式。

#### 2\.2\.4 设备协议适配层

屏蔽底层网络字节流差异，标准化传感器数据。核心功能：自定义二进制协议/Modbus TCP协议编解码、TCP粘包分包处理、数据帧校验（长度校验、CRC校验）、原始报文解析、标准化传感器数据结构体封装。

#### 2\.2\.5 持久化与工具支撑层

系统基础能力支撑。核心功能：本地日志分级记录、INI/JSON配置文件解析、传感器历史数据数据库存储、数据序列化与反序列化、高精度定时采集、系统工具类封装。

### 2\.3 核心数据流流程

1. Boost\.Asio异步接收远程传感器原始字节流报文；

2. 协议层完成粘包分包处理，校验并解析出完整有效数据帧；

3. 业务层对原始数据进行滤波、异常过滤、告警判定等预处理；

4. 通过线程安全队列/跨线程信号槽将标准化数据推送至UI层；

5. Qt主线程接收数据，刷新实时曲线、界面数值、设备状态及告警信息；

6. 异步线程批量将历史数据写入数据库，完成数据持久化。

## 3 核心模块详细设计

### 3\.1 Boost\.Asio网络通信模块

#### 3\.1\.1 线程模型设计

独立创建网络工作线程，单独运行 `io_context` 事件循环，与Qt主线程完全隔离。通过 `executor_work_guard`守护IO上下文，避免无事可做时自动退出，保障网络服务常驻运行。所有异步读写回调均执行于网络子线程，不参与UI操作。

#### 3\.1\.2 可靠性保障机制

- **心跳保活**：基于Boost\.Chrono高精度定时器，定时发送心跳包，检测设备在线状态；

- **断线重连**：超时无应答、网络异常、设备断开时，自动触发重连机制，支持重连次数限制与间隔策略；

- **缓冲区管理**：采用环形缓冲区收发数据，避免数据丢失、溢出，适配高频采集场景；

- **多设备管理**：以设备ID为唯一标识，通过Map容器统一管理多个传感器连接会话。

### 3\.2 数据协议与解析模块

#### 3\.2\.1 自定义通信协议格式

采用「定长帧头\+可变载荷\+校验位」标准工业协议，解决TCP字节流无边界问题，协议结构：
\[4字节帧长\]\[2字节设备ID\]\[N字节传感器数据载荷\]\[CRC校验码\]

#### 3\.2\.2 数据解析规则

1. 优先异步读取固定帧头，解析数据总长度；

2. 根据帧长读取对应载荷数据，拼接完整数据帧；

3. 校验CRC码与数据长度，非法报文直接丢弃并重置缓冲区；

4. 合法报文解析为温度、压力、湿度、振动等标准化测点数据。

### 3\.3 跨线程数据通信模块

核心约束：**仅Qt主线程可操作UI控件，子线程禁止直接刷新界面**。采用双重保障方案：

- 跨线程信号槽：使用 `Qt::QueuedConnection` 模式，通过共享指针 `std::shared_ptr` 传递数据，减少内存拷贝；

- 线程安全队列：业务层维护无锁/互斥环形队列，Qt主线程通过QTimer定时拉取数据，避免数据堆积。

### 3\.4 实时数据可视化模块

#### 3\.4\.1 绘制优化策略

- 帧率限制：固定UI刷新帧率（30FPS），丢弃超额采样数据，避免界面过载；

- 滑动窗口机制：限制曲线最大显示点数，自动清理历史冗余数据，防止内存持续增长；

- 硬件加速：开启QCustomPlot OpenGL硬件渲染，提升高频绘图流畅度；

- 算力隔离：数据滤波、异常分析、频谱计算等耗时操作均在子线程完成。

### 3\.5 数据持久化模块

采用异步批量落盘策略，避免单条数据频繁IO阻塞主线程与采集线程。独立开辟数据库工作线程，缓存高频采集数据，定时批量写入SQLite数据库，同时支持历史数据回放、CSV数据导出功能。

### 3\.6 配置与日志模块

- **配置管理**：基于Boost\.PropertyTree解析INI/JSON配置文件，统一管理设备地址、端口、采样频率、告警阈值、刷新参数等；

- **日志管理**：适配spdlog日志组件，分级记录网络日志、采集日志、告警日志、异常日志，支持日志分级输出与文件留存。

## 4 系统重点与难点分析及解决方案

### 4\.1 Boost\.Asio异步线程安全问题

**难点痛点**：异步回调执行线程不固定，新手易出现子线程操作UI、多线程共享Socket、IO上下文混乱问题，引发程序崩溃、内存越界、数据错乱。

**解决方案**：严格隔离线程职责，网络线程仅负责数据收发、报文解析与数据封装；所有UI操作、控件更新全部通过跨线程信号槽抛至Qt主线程；每个传感器会话独立管理生命周期，连接关闭后禁止二次读写。

### 4\.2 高频采集下UI卡顿与数据丢失

**难点痛点**：传感器高频采样（100Hz\~1kHz）时，海量数据持续涌入，UI刷新不及时导致队列堆积、内存暴涨、曲线卡顿、数据丢失。

**解决方案**：设置消息队列最大容量，队列满时自动丢弃老旧数据；UI层实现降采样策略，单帧刷新周期内保留平均值/最新值；限制曲线展示数据总量，杜绝无限数据累积。

### 4\.3 TCP粘包、分包与网络容错问题

**难点痛点**：TCP为无边界字节流，网络抖动、设备异常断电易导致粘包、分包、非法报文，引发解析失败、程序卡死。

**解决方案**：标准化定长帧头协议，通过长度\+CRC双重校验机制过滤非法数据；设置缓冲区自动重置机制，异常报文直接清空缓冲区重新接收；精准识别网络正常关闭、超时、异常断开等不同状态，差异化执行重连逻辑。

### 4\.4 多传感器并发会话管理

**难点痛点**：多设备同时接入时，连接状态、数据通道、采集任务难以统一管理，易出现设备状态错乱、数据交叉污染。

**解决方案**：封装独立SensorSession会话类，一对一绑定单个传感器设备；通过设备ID映射管理所有会话，统一提供启停采集、状态查询、断开连接接口，实现批量设备管控。

### 4\.5 大数据量跨线程拷贝性能问题

**难点痛点**：高频信号槽传递大型传感器结构体，频繁值拷贝导致CPU占用过高、系统资源浪费。

**解决方案**：统一使用`std::shared_ptr<const 数据结构体>` 作为信号参数，利用共享指针引用计数机制，规避数据深拷贝，大幅降低CPU开销。

### 4\.6 实时性与数据持久化平衡问题

**难点痛点**：实时采集刷新对延迟要求极高，单条数据实时入库会产生大量IO阻塞，影响采集实时性。

**解决方案**：分离采集线程与数据库IO线程，采用异步批量写入机制，缓存多条数据后统一落盘，兼顾数据实时展示与持久化完整性。

### 4\.7 跨平台编译部署兼容问题

**难点痛点**：Boost库编译配置复杂，Qt跨平台依赖库繁多，Windows/Linux平台编译、运行易出现兼容报错。

**解决方案**：基于CMake编写统一跨平台构建脚本；Boost优先静态编译，减少动态库依赖；分别适配Linux epoll网络模型与Windows网络机制，统一字符集与编译参数。

## 5 系统部署架构方案

### 5\.1 一体化单机方案（默认方案）

采集通信、业务处理、UI可视化全部集成在单个进程内，部署简单、无需额外服务依赖，适合中小型采集系统。缺点为单进程耦合度高，核心逻辑异常会导致整体程序退出。

### 5\.2 进程分离方案（大型工业场景）

前后端进程解耦：后端纯C\+\+\+Boost后台服务，常驻后台负责数据采集、解析、存储；前端Qt GUI仅负责可视化与交互。优势为UI重启、异常不会影响数据采集，系统稳定性更高，适合大规模多设备采集场景。

## 6 工程目录结构

```Plain Text
src/
├── net/           # Boost.Asio网络会话、异步通信、连接管理
├── protocol/      # 传感器协议编解码、报文校验、粘包分包处理
├── business/      # 数据滤波、告警判定、采集任务调度
├── ui/            # Qt窗口界面、曲线绘图、交互逻辑、告警展示
├── storage/       # 数据库读写、数据持久化、数据导出
├── common/        # 数据结构体、日志、配置解析、工具函数
main.cpp           # 程序入口
CMakeLists.txt     # 跨平台编译配置脚本
```
